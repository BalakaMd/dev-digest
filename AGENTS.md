# DevDigest

Local-first AI pull-request reviewer. This is the **course starter template**:
it is intentionally minimal, and empty placeholders are expected, not bugs.

## Stack

Node ≥22 · pnpm ≥10 · TypeScript 5.7 · Postgres 16 + pgvector (Docker) ·
Fastify 5 · Drizzle ORM · Next.js 15 / React 19 · Zod 3 · vitest 2

## Commands

```sh
./scripts/dev.sh              # from zero: docker → migrate → seed → API + web
./scripts/dev.sh --db-only    # Postgres only
./scripts/e2e.sh              # hermetic e2e on alternate ports (local only)
cd server && pnpm db:migrate  # migrations are NOT applied on boot
```

Verify, per package: `pnpm test` / `pnpm typecheck` (`npm` in `reviewer-core` and
`e2e`; server splits its suites — see `server/AGENTS.md`). There is **no linter
or formatter** here — CI runs typecheck and tests only; do not invent `lint`.

## Git

**Never run `git commit` or `git push` without explicit permission.** Reading
history, `git diff` and staging are fine; publishing history is not. Ask every
time — an earlier approval never carries over. Leave work in the tree and offer.

## Insights

Every module keeps an `INSIGHTS.md` — what earlier sessions learned the hard way.
Read the relevant one **before** non-trivial work; add to it afterwards only when
something genuinely new turned up. The `engineering-insights` skill holds the
rubric, the bar, and the dedup procedure.

## Conventions (non-default — not inferable from the code)

- **This is NOT a monorepo.** Each package has its own `package.json` and its own
  lockfile. `server`/`client` use pnpm, `reviewer-core`/`e2e` use npm. Never add
  workspace fields.
- Cross-package code is shared through **tsconfig path aliases**, not published
  modules.
- `server` imports **raw TypeScript** from `reviewer-core/src` (tsx in dev,
  vitest in tests). `reviewer-core` never emits JS — its `build` is a type-check.
- `@devdigest/shared` is canonical in `server/src/vendor/shared`;
  `client/src/vendor/shared` is a copy. Changing a contract means syncing both.
- Server modules are registered **statically** in `server/src/modules/index.ts`
  (not autoload — dynamic `import()` of `.ts` is not portable across tsx/vitest).

## Naming

- Server module: `modules/<name>/routes.ts` — the folder name *is* the module name.
- Server test: a DB-backed one **must** end `*.it.test.ts`; CI splits on that suffix.
- Client feature: `_components/<PascalCase>/` plus a sibling `*.test.tsx`.
- Migration: `NNNN_<slug>.sql` — drizzle-kit generates it; never hand-name one.

## Gotchas

- Postgres listens on **5433**, not 5432. Parts of the READMEs still say 5432.
- The DB schema already contains tables nothing writes to yet. Empty ones are
  normal — do not "clean them up".
- The app boots with no API key, but a review cannot run without one (the
  built-in agents use the `openrouter` provider).
- Secrets never live in the DB or in git: `~/.devdigest/secrets.json`, mode
  `0600`, with `process.env` as fallback.

## Do not touch

- `*/vendor/**` — vendored copies; edit the canonical source instead
- `.claude/skills/**` — vendored, managed via `skills-lock.json` (source hashes).
  Ours, edit freely: `engineering-insights/`, `onion-architecture/`
- `server/src/db/migrations/*.sql` — generated by drizzle-kit; never edit an
  applied migration, add a new one
- `pnpm-lock.yaml` / `package-lock.json` — never hand-edit; change them only by
  running that package's own installer. Each package owns its lockfile
- `clones/` — working checkouts of imported repos, git-ignored
